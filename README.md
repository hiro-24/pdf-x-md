# PDF Note

PDF を縦にスクロールして読み、メモを付けたいページでは **横にスクロール**すると、そのページ専用の
Markdown メモが並ぶビューアです。

```
         固定          ← 横スクロール（そのページのメモ） →
        ┌────────────┬────────────┬────────────┐
   ↑    │  p.1       │  メモ A    │  メモ B    │
   │    ├────────────┼────────────┴────────────┤
  縦    │  p.2       │  （メモなし）            │
スクロール ├────────────┼─────────────────────────┤
   │    │  p.3       │  メモ C    │             │
   ↓    └────────────┴────────────┴────────────┘
           ↑ページは定位置に残り、メモがその横を流れます
              （ページは右端に置くこともできます）
```

## 使い方

```bash
npm install     # pdf.js の cmaps / fonts / wasm も public/ に配置されます
npm run dev     # http://localhost:5174
npm test        # テストは自分用のサーバーを立てます（tests/README.md 参照）
```

PDF をドロップすると読み込まれます。データが外部に送信されることはありません。

保存先は 2 層です。作業用のコピーはブラウザの IndexedDB に置かれ、**同期フォルダ**を
設定しておくと、メモは編集のたびに実ファイルとして書き出されます。ブラウザのデータを
消しても、同じ PDF を入れ直せば指紋照合でメモが再接続されます。

## できること

- **縦スクロール**でページを読む（表示中のページ周辺だけ描画する仮想化つき）
- **横スクロール**でそのページの Markdown メモを見る／書く。1ページに何枚でも追加でき、
  並び替えも可能。**PDF は端に固定されたまま**なので、メモを何枚並べてもページは見えています
- **本全体のまとめ**（ツールバーの「まとめ」か <kbd>m</kbd>）: ページに紐づかない
  Markdown を持てます。読みながら書き足していくためのもので、**どのページにいても
  開いたまま**です。**何枚でも作れて**（＋ボタン）、上のタブで切り替えます。
  タブの名前は**1行目**です——「# 読書メモ」と書けばタブは「読書メモ」になります。
  PDF と反対側の端に出るので、ページは隠れません。幅は内側の端をドラッグして
  変えられます（ダブルクリックで戻ります）
- **Tab で字下げ**（半角スペース4つ）。箇条書きの行なら、カーソルがどこにあっても
  行ごと入れ子にします。複数行を選んでいればまとめて動きます。`Shift + Tab` で戻ります
- **書くのを助けるボタン**（見出し・太字・箇条書き・番号つき・チェックボックス・引用・コード）。
  選んだ行すべてに効き、もう一度押すと外れます。箇条書きの途中で Enter を押すと次の項目が
  続き、空の項目で押すと抜けます
- **テキスト選択 → ハイライト**（4色）。ハイライトをクリックすると色変更・削除・引用
- 選択テキストを **`> 引用`** としてメモに送る
- **メモ一覧**パネルからページへジャンプ
- メモとハイライトを **1本の Markdown ファイルに書き出し**
- **同期フォルダ**（Chrome / Edge）: 選んだフォルダへ `<PDF名>.notes.json` と `.md` を
  自動保存。Google ドライブ・iCloud Drive・Dropbox の中を選べば、そのままバックアップと
  複数 PC 間の同期になる
- **JSON バックアップ／復元**: どのブラウザでも使える手動の避難経路
- 前回読んでいたページから**自動で再開**。開いた直後に「前回の続き p.31 から開きました」と
  出て、その場から先頭へも戻れる。同じ PDF を入れ直しても重複エントリを作らない
- **しおり**: 読んでいるページに <kbd>b</kbd> かツールバーから挟む。1つの PDF に何個でも
  置け、名前をつけられる。パネルの一覧から飛べて、挟んだページには右上に 🔖 が出る
- **ライブラリのテーブル管理**: タイトル・ページ数・メモ数・最終閲覧・タグの列。
  列見出しで並び替え、タイトルはその場で変更できる
- **表紙で探す**（検索欄の右「表紙」）: 本棚のように表紙を並べる。表紙をクリックで開く。
  検索とタグの絞り込みはそのまま効き、並び順は選べる。どちらの見方だったかは覚えている
- **タグ**（Gmail のラベル相当）: 1つの PDF に何個でも付けられる。色は 9 色から選べ、
  作成時にも作成後にも変更できる（未指定なら使用数の少ない色が自動で割り当てられる）。
  タグをクリックすると絞り込み。複数選ぶと AND 条件になる
- **タグの管理テーブル**（「タグを管理」から開く）: 全タグを一覧で、追加・色の変更・
  説明文の記入・削除ができる。説明文はチップとタグメニューのツールチップに出る。
  使用数の列で、どのタグが働いていないかが分かる。削除すると、そのタグが付いた
  PDF からも外れる（何件から外れるか確認してから実行）
- **横断検索**: タイトル・ファイル名・タグ名に加えて、**メモとハイライトの本文**まで対象。
  空白区切りで AND 検索
- タイトルにカーソルを置くと**表紙（1ページ目）のサムネイル**が出る

### キーボード

| キー | 動作 |
| --- | --- |
| <kbd>b</kbd> | 読んでいるページのしおりを挟む／外す |
| `n` | 表示中のページにメモを追加 |
| `m` | 本全体のまとめを開く／閉じる |
| `j` / `k` | 次 / 前のページへ |
| `Tab` / `Shift + Tab` | 字下げする / 戻す（箇条書きなら入れ子にする） |
| `⌘/Ctrl + Enter` | メモの編集を終えてプレビュー |
| `Esc` | 編集を抜ける |

### メモを書く

| | |
|---|---|
| 上のボタン | 見出し・太字・箇条書き・番号つき・チェックボックス・引用・コード |
| Enter | 箇条書きの途中なら次の項目。空の項目なら抜ける |
| ⌘/Ctrl+Enter | 書き終わってプレビューへ |
| Esc | 編集をやめる |

ボタンは選択範囲が触れている行すべてに効きます。もう一度押すと外れ、
箇条書きから番号つきへは重ねずに置き換わります。

ページごとのメモと、本全体のまとめは別物です。前者はページの横に並び、そのページを
見ながら読みます。後者はどのページからでも開けて、書き出すときはファイルの先頭に
「まとめ」として出ます（複数あるときは作った順に並びます）。

### 表示

- **全体**（既定）… 1ページ全体が画面に収まる倍率。1行 = 1画面になるので、
  メモカードが画面より高くなりません
- **幅** … 横幅に合わせる。長いページを読むとき用
- **PDF の位置**… 端とページの間の余白をドラッグすると、ページが左右に動きます。
  窓の幅から自動で決めた位置が既定で、動かすと次からはその位置を使います。
  ダブルクリックで自動に戻ります。メモが入らなくなる所までは動きません
- **固定 左 / 右 / なし**（既定は左）… 横スクロール中も PDF を左右どちらかの端に
  留めておきます。メモは反対側に並び、ページの裏を流れていきます。「なし」にすると
  PDF もメモと一緒に流れます（幅の広いメモを画面いっぱいで読みたいとき用）。
  設定は次に開いたときも残ります

## クラウドと組み合わせる

専用の連携は要りません。デスクトップ同期アプリが作るローカルフォルダを、そのまま
同期フォルダに指定します。Google ドライブなら次の場所です。

```
~/Library/CloudStorage/GoogleDrive-<アドレス>/マイドライブ/
```

Chrome のフォルダ選択ダイアログは macOS の `~/Library` 配下を拒否することがあります。
その場合は同期フォルダを `~/Documents/PDFノート` など普通の場所に作り、Google ドライブ
アプリ側の「パソコンのフォルダを同期」でそのフォルダを追加してください。結果は同じです。

複数の PC で同時に編集すると、同期アプリが競合コピーを残します。`findBundle` は同じ
指紋のファイルをすべて見て `savedAt` が最新のものを採用するので、競合コピーが増えても
壊れません。

## 設計メモ

- **タイトル**は PDF の埋め込みメタデータから取り、なければファイル名にします。この欄には
  producer が残したゴミ（`Microsoft Word - 原稿.docx`、印刷元の URL、`untitled`）が
  入っていることが多いので、`cleanTitle` で落としてから採用します。
- **タグは名前で持ちます**。id ではありません。別のマシンに渡ったときに意味を保つのは
  名前のほうだからです。色は同期フォルダの `_tags.json` に置かれ、複数の PC で揃います。
  マージは**名前の和集合**です。全体を新しい方で上書きすると、前回の同期以降に
  別の PC で作られたタグが消えてしまうためで、タイムスタンプで決めるのは
  「両方が知っている名前の色」だけです。
- **タグの色は 1 色につき 1 つの基準色**（`--tag-hue`）から作ります。チップの背景は
  その色の薄いミックス、ピッカーの色ドットは原色で、定義は 1 箇所です。
- **しおりと `lastPage` は別物です**。`lastPage` はスクロールに追従する暗黙の現在位置で、
  1つの文書に1つ。しおりは読者が意図して置く目印で、いくつでも置けて、読み進めても
  消えません。前者は「開いたら続きから」、後者は「あとで戻りたい場所」を担当します。
- **ページへ跳ぶときは、止まるまで狙い直します**（`src/lib/settle.ts`）。行の高さは
  開いた直後の 1〜2 フレームだけ前の倍率のままで、そこで一度だけ跳ぶと 1 ページぶんの
  誤差 × ページ番号だけ手前に落ちます。短い PDF なら 1〜2 ページ、長い PDF ではもっと
  大きくずれます。対象の行が動かなくなるまで毎フレーム狙い直し、途中でホイールに
  触れられたらそこで諦めます。前回位置の復元としおり・メモへのジャンプが同じ関数を
  使います。近距離のジャンプは滑らかに動かすので、その間は狙い直しません
  （毎フレーム狙い直すとアニメーションを潰してしまうため）。`scrollend` を待ちます。
- **ショートカットが見るページ番号は ref から取り、`useLayoutEffect` で更新します**。
  React の通常の副作用は**描画のあと**に走ります。つまりツールバーに新しいページ番号が
  出てから listener が作り直されるまでに数ミリ秒の隙間があり、そこで `b` を押すと
  一つ前のページのしおりが外れました（p.30 で押して p.4 のしおりが消える）。
  `useLayoutEffect` は描画の前に走るので、表示と listener がずれません。しおりの一覧も
  同じ理由で ref から読みます。クリックのハンドラは同じ描画のものが渡っているため
  この問題はなく、window に張った listener だけの話です。
- **同期の勝ち負けは、2 つの時計で別々に決めます**。メモ・ハイライト・しおりは
  「中身の更新時刻どうし」で比べます。ファイルの `savedAt` と比べてはいけません——
  それは書き込んだ時刻で、常に中身の編集より少し後になるため、フォルダ側が毎回勝って
  しまいます（メモが 1 件も無い文書では、ローカル側の基準が 0 なので確実に負けます）。
  読書位置・タイトル・タグは note と無関係に動くので、専用の `metaAt` で比べます。
  これが無いと、フォルダの `lastPage` は「最後にメモを編集した時のページ」でしかなく、
  何時間読み進めても開き直すたびにそこへ引き戻されます。フォルダ側の `lastPage` は
  ライブラリへ戻るときとタブを隠すときに書き出して更新します。
- **右固定は `sticky` だけでは足りません**。`position: sticky` はスクロールするものが
  無いと何もしないので、メモの無いページ（＝たいていのページ）ではページが flex の
  自然な位置、つまり左に残ってしまいます。左固定はそれが偶然正解なので気づけません。
  ページの手前のレーンに `margin-left: auto` を置いて余白を吸わせ、右端に寄せています。
  行が伸びて実際にスクロールするようになると余白が無くなり、auto は 0 になって、
  そこから先は sticky が仕事を引き継ぎます。
- **右固定は `flex-direction: row-reverse` で、レーンごと反転させます**。半分だけ
  鏡にすると、1枚目のメモがページから一番遠い位置に来てしまいます。反転させると
  1枚目がページの隣に付き、2枚目以降がそこから遠ざかる——左固定と同じ関係が、
  鏡に映った形で成立します。スクロールの原点も右端に移るので、行を開いた時点で
  1枚目がページの横に見えます。DOM の並びは「ページ → そのページのメモ」のままなので、
  読み上げ順とタブ順は左右どちらでも変わりません。
- **反転したときは `scroll-snap-align` も `end` にします**。`start` が指すのは
  書字方向の先頭、つまり物理的な左であって、`flex-direction` では動きません。
  そのままだとメモが窓の左端に吸い付いてしまい、ページから一番遠い所で止まります。
- **ページを動かす取っ手は余白そのものです**。ページの上に置けないためです——
  ページ上のドラッグは文字を選ぶ操作で、取り上げるわけにいきません。端と
  ページの間の帯には他にすることが無いので、そこが取っ手になっています。
  ドラッグ中は React の状態ではなく `--page-gutter` を直接書き換えます。
  状態にすると 1 フレームごとに全ページぶんの行が再描画されるためです。
  確定するのは指を離したときだけです。
- **ページの位置と幅は `--page-gutter` と `--pdf-lane` の2つで決めます**。`.pages` に
  現在の倍率から計算して置き、メモの幅もスクロールのスナップ位置もそこから出ます。左の余白はメモ1枚ぶんを確保した残りの半分で、
  窓が広いほど広がります（上限 200px）。固定なのだから窓の左端に貼り付ける、では
  読む位置として低すぎるためです。狭くなれば 24px まで素直に詰まります。これが無いと、メモは固定されたページの**裏**にスナップして、送ったのに
  何も見えないという状態になります。窓が狭くてメモの居場所が無くなるときは固定を
  やめます。固定したまま隠すのでは、苦情の向きが変わるだけなので。
- **ページの下に帯を置きません**。しおりの 🔖 だけをページの右上に浮かせています。
  帯は高さを取り、その高さは全ページぶん効いてくるからです。ページ番号は
  ツールバーに出ているものと同じなので、繰り返すために面積を払う理由がありません。
  以前は 🔖 の隣に「メモ N 件 →」も出していました（押すとメモを1枚ずつ送れました）。
  やめたのは同じ理屈です——メモのあるページすべてに、読むたび見えるラベルが
  載ることになるためです。メモへは横スクロールで届きます。
  帯をやめたぶん `CHROME_HEIGHT` が 94 → 66 に下がり、1000px の窓で 107% → 111%、
  面積にして約 6% ページが大きくなります。
- **タグの説明はタグ自身が持ちます**。`Tag` に `description` を足しただけなので、
  パレットの保存経路（IndexedDB の `settings`、同期フォルダの `_tags.json`）にも
  マージ規則にもそのまま乗ります。名前の和集合を取るとき、タグは丸ごと運ばれるためです。
- **タグの削除はパレットだけでは終わりません**。各 PDF の `tags` からも名前を外します。
  残したままだと、次に同期フォルダを読んだときに名前ごと復活してくるためです。
- **書くのを助ける処理は文字列の関数です**（`src/lib/markdown-edit.ts`）。textarea を
  受け取らず、文字列と選択範囲だけを見ます。半分だけ選ばれた行をどう数えるか、
  操作のあとカーソルがどこへ行くか——細かいところはテストで固定したいためです。
  空行の扱いは二通りあります。選択の**中**にある空行は段落の切れ目なので飛ばし、
  空行**しかない**ときは印を入れます。後者は新しいメモそのもので、最初にボタンを
  押す場所だからです。またカーソルだけのときは行を選び直さずカーソルのまま返します。
  印をつけた行を選択状態にすると、次に打った一文字がその印を消してしまうためです。
- **Enter は2種類あります**（`src/lib/ime.ts`）。日本語は IME を通って入るので、
  変換を確定させる Enter がページにも届きます。キーとしては本物の Enter と
  区別がつかず（`key` は "Enter"、`keyCode` は 13）、違うのは `isComposing` だけです。
  見分けずに扱うと、箇条書きでは確定した瞬間に次の項目が足されて中身ごと二重になり、
  入力欄ではまだ読みの途中のものが確定として送られます。Enter を見る場所は
  すべて `converting(event)` で先に弾いています——メモ・タグ検索・タグ名・
  タグの説明・タイトルの変更の5か所です。`preventDefault` はしません。確定の
  文字入力は IME 側が済ませており、こちらが止めるものではないためです。
- **Tab はフォーカス移動より字下げを優先します**。入力欄からキーボードだけで
  抜けられなくなるのは本来まずいので、`Esc` という出口があることが条件です。
  字下げはタブ文字ではなく半角スペース4つにしています。タブ文字の見た目の幅は
  読む道具ごとに違い、Markdown は箇条書きの深さをスペースの数で決めるためです。
- **本全体のまとめは「0 ページ目のメモ」です**。ページ番号は 1 から始まるので、0 は
  どのページとも衝突しません。普通のメモとして持つことに意味があります——保存も同期も
  書き出しも検索も、すでにメモを扱っている経路がそのまま通り、そして 0 番の行は
  存在しないので、どのページのレーンにも現れません。別の入れ物を足すと、同期の
  マージ規則からライブラリの検索まで、同じことをもう一度書くことになります。
  複数枚も同じ話で、1ページに何枚もメモを置くときと同じ `order` でタブの並び順に
  なります。出しわけが要るのは2か所だけです。しおり・メモの一覧（ページの索引なので
  外す）と Markdown の書き出し（`## p.0` ではなく `## まとめ` として先頭に置く）。
- **まとめの名前は1行目です**。タイトルの欄は作っていません。メモに名前欄が無いのは
  ページのメモも同じで、`firstLine()` が記号を落として1行目を取り出します。欄を足すと
  「名前と中身の見出しが食い違う」状態を作れてしまい、どちらが正かを決める規則が
  要ります。1行目そのものを名前にすれば、食い違いようがありません。
- **検索はメモ本文まで見ます**。起動時に全メモを読んで docId ごとに連結するだけの
  素朴な作りです。別のインデックスを持つと同期のずれが新しいバグになるので、
  この規模では読み直すほうが確実です。
- **重なるものは全部、祖先の枠から出します**。テーブルは `overflow-x: auto`、
  タグメニューの一覧は `overflow-y: auto` で、どちらもスクロール枠です。中に
  絶対配置したものは切り取られます。タグメニューと表紙プレビューはポータルで
  body に、色のパレットは `position: fixed` で出します。切り取られると
  「押しても何も出ない」に見えるので、タグが増えるまで気づけません。
- **表紙は取り込み時に一度だけ焼いて** IndexedDB の `thumbs` に持ちます。ホバーのたびに
  PDF を開き直すのでは間に合いません。表紙を持たない古いエントリは、最初のホバーで
  生成してから同じ場所にしまいます。プレビューはテーブルの左の余白に開きます
  （右に開くと、見ようとしている行そのものを覆ってしまうため）。
- **表紙ビューでは、表紙の要求を1本にまとめます**。同じ表紙への同時要求は1つの
  Promise に畳み、まだ焼けていないものは1つずつ順に焼きます。表紙を持たない
  ライブラリを本棚で開くと、そうしないと全 PDF を同時に解析しにいきます。
  タイル自身も IntersectionObserver で、画面に近づいてから初めて要求します。

## テスト

`npm test` だけで走ります。名前を渡すと一部だけ（`npm test shelf lanes`）。
実際の Chrome を Playwright で動かすので、詳細は [tests/README.md](tests/README.md) を見てください。

## 開発の進め方

`main` は常に動く版にしておきます。手を入れるときは枝を切ります。

```bash
git switch -c feat/xxx        # 作業用の枝を作る（直す時は fix/xxx）
# ... 実装 ...
npm test                      # 全部緑を確認
git switch main
git merge --no-ff feat/xxx    # main に取り込む
git branch -d feat/xxx        # 枝を片づける
git push
```

`--no-ff` を付けるのは、「この機能はこの何コミット」という括りを履歴に残すためです。
付けないと main に平らに並んでしまい、あとから境目が分かりません。

やめたくなったら、こうです。跡形もなく消えます。

```bash
git switch main
git branch -D feat/xxx        # 大文字の D は「未取り込みでも消す」
```

節目には印を打ちます。

```bash
git tag -a v0.2.0 -m "何が入ったか"
git push --tags
```

おかしくなったときは `git switch --detach v0.1.0` でその時点に戻って確かめられます。
戻るときは `git switch main` です。

### release / hotfix を足す日

いまは使いません。**インストール型のアプリとして配布物を出した日**が引き金です。
main に push すれば直る、が成り立たなくなって初めて、この2つが仕事をします。

| 枝 | 切る時 | 何のため |
|---|---|---|
| `release/0.3` | 出す直前 | 出す版を固定し、その上だけで仕上げる。並行して次の開発を進められる |
| `hotfix/0.2.1` | 出した版に不具合 | tag から切って直し、main にも作業中の枝にも戻す |

`develop` は、「次に出す版には入れたくないが、取り込んではおきたい」ものが出てきたら
足します（`git switch -c develop main` の一行です）。1人で開発している間は、
merge が毎回2回になるだけで得るものがありません。

## 既知の注意点

- **pdf.js の速度を自動化ブラウザで測らないこと。** Playwright（CDP）は pdf.js の worker に
  接続するため、メッセージ往復が 20〜100 倍に膨らみます。素の Chrome なら
  `getOperatorList` は 23ms ですが、CDP 経由では 4.5 秒かかり、ページが白紙のまま
  固まっているように見えます。以前これを「minified worker のバグ」と誤診しました。
  実測はページから localhost へ結果を POST させるなど、CDP を介さない方法で行ってください。
- **ポートは固定です（5174）。**ブラウザは**ポートが違えば別のサイト**として扱います。
  保存領域（PDF・メモ・タグ）も、同期フォルダへの許可も、**最初に開いた URL ごと**に
  持ちます。`strictPort` を外すと、5174 が塞がっているときに Vite が黙って別の番号で
  起動し、次に立ち上げたときには空のライブラリが出てきます——実際にそうなりました。
  テストは 5175 に自分のサーバーを立てるので、ぶつかりません。
  もし「ライブラリが空になった」ときは、まず**アドレスバーのポート番号**を見てください。
- **同期フォルダが復元するのはメモだけです。**PDF 本体はフォルダに入りません
  （`.notes.json` と `.md` だけです）。ブラウザのデータが消えた場合は、同じ PDF を
  入れ直すとフォルダ側のメモが自動で合流します。逆に言うと、**PDF を入れ直すまでは
  フォルダを繋いでも何も表示されません**。
- **同期フォルダは Chrome / Edge 専用**です（`showDirectoryPicker` 非対応の Safari・
  Firefox では自動的に JSON バックアップの案内に切り替わります）。Chrome は
  セッションをまたぐとフォルダへの許可を落とすことがあり、その場合は
  ライブラリ画面に「再接続」ボタンが出ます。
- PDF 本体は書き換えません。ハイライトとメモはアプリ側に保存されます
  （注釈を焼き込んだ PDF の書き出しが必要なら `pdf-lib` の追加が要ります）。
